ROLY

A tiny, stable programming language. Integer arithmetic, strings, lists, loops, conditions, jumps — nothing else. This single page is the complete language guide.

Running Roly

Two commands drive the engine. run executes a file, exec executes inline code:

roly run program.roly
roly exec 'x = 1 + 2 print(x)'
roly exec 'x = 0; while (x < 5) { x += 1 }; print(x)'

Standard output shows only what print emits. Nothing else is printed — there is no dump of variables after the run, so a program that ends without printing produces no output.

Every failure is a single clean error line on standard error, and the exit code is 1. Lexing and parsing errors carry the position; runtime errors name the problem:

error: line 1, column 5: expected a statement, got '.'
error: division by zero
Standard library modules are imported with !import; your own modules are looked up next to the file that imports them. The engine also ships as a standalone executable (roly / roly.exe); its lib/ folder must stay next to it.

Values

Roly has exactly five kinds of values:

  • Integers — arbitrary size, written in decimal digits: 42, 0, 1234567
  • Floats — decimal fractions and exponent forms: 1.5, -0.25, 2e3, 1.5e-2; binary IEEE-754 doubles with Python's arithmetic
  • Booleans — written TRUE and FALSE, always in capital letters; also produced by comparisons
  • Strings — double-quoted, may contain any characters: "hello world"
  • Lists — ordered sequences of values, built and read through built-ins: [1, 2, 3]
Integers and floats mix freely in arithmetic and comparison — 1 + 0.5 is 1.5, 1 == 1.0 is True — the result is a float as soon as one side is a float. Booleans never mix with arithmetic: x = 1 < 2 y = x + 1 is a runtime error. Strings never convert implicitly: "1" == 1 is simply False, and so is TRUE == 1.

Variables

A variable is created by assignment. Names are letters, digits, and underscores, starting with a letter or underscore. There is a single global scope — blocks do not create new scopes.

x = 10
total = x * 2
_counter = 0

Compound assignment updates a variable in place with an arithmetic operation:

x += 5
x -= 3
x *= 2
x /= 2
Reading a variable before it is assigned is a runtime error: undefined variable 'x'. Division in /= follows the same rule as /: floor for two integers, true division when a float is involved.

Assigning again is always allowed — variables are freely reassignable, and a variable may hold a different type later. There is no declaration keyword: the first assignment creates the variable.

x = 5
x = "five"      // fine — the same name now holds a string
Some names are taken: the keywords and the built-in function names (len = 5 is an error). Standard library names are yours until you import them — after !import math {gcd} the name gcd means that function and cannot be redefined.

Comments

// starts a comment that runs to the end of the line. Everything from // onward is ignored, so the rest of the line is free for notes. // inside a string is part of the string.

x = 1 + 2 * 3      // computes the multiplication first
total = x * 2      // total is 14

// a whole-line comment
name = "http://roly"  // the // here is string content
There are no block comments — a long note is several // lines.

Arithmetic

Four operators, with the usual precedence — multiplication and division bind tighter than addition and subtraction. Parentheses group. Integers and floats mix freely; the moment either operand is a float, the operation is float arithmetic.

1 + 2 * 3          // 7
(1 + 2) * 3        // 9
100 / 5 / 2        // 10, division is left-associative
10 - 3 - 2         // 5, subtraction is left-associative
1 + 0.5            // 1.5
2 * 1.5            // 3.0 — a float anywhere makes a float result
OperatorMeaningExample
+addition (numbers) or concatenation (string)"a" + "b" is "ab"
-subtraction10 - 4 is 6
*multiplication6 * 7 is 42
/floor division for two integers, true division when either side is a float(0 - 7) / 2 is -4, 7.0 / 2 is 3.5
Division of two integers always floors toward negative infinity; if either operand is a float the division is exact. Division by zero is a runtime error either way. Negative values can be written directly with a unary minus: -5, -x, --3, -1.5. Negating a boolean or string is a runtime error.
Floats are IEEE-754 doubles and behave exactly like Python's: 0.1 + 0.2 is 0.30000000000000004, and values beyond the double range become inf. Mixing an integer too large for a double with a float is a runtime error — integer too large to convert to float — as is float() of such an integer. No rounding is ever applied for you — convert deliberately with int() or str(). Both operands of + must be numbers, or both strings: "a" + 1 is a runtime error — use str() or int() first. There is no string repetition: "ab" * 2 is an error; build strings with + in a loop. A float literal needs digits on both sides of the dot — 1.5 works, while 1. and .5 are parse errors, so write 1.0 and 0.5. Exponent forms are 2e3, 1.5e-2. There are no hex or binary literals; the library's binary() and hex() render integers instead.
A statement's pieces must stay on one line: an operator that starts on a new line is a parse error, and so is an assignment operator separated from its name — x = 5 followed by -2 on the next line does not parse as x = 5 - 2, and x followed by = 5 on the next line does not parse as an assignment to x. The same rule covers the parenthesis after a keyword: if, while, print and a function's parameter list must open their ( on the same line, a block's { must sit on the line of its if (...) / else / while (...) / fn name(...), a function's name must follow fn, and an import brace list stays on one line. To split a long expression, open a bracket first — inside ( ) and [ ] newlines are allowed: x = (1 + ⏎ 2) and l = [1, ⏎ 2] both parse.

Comparisons

Comparisons produce booleans. They sit at a single precedence level, below arithmetic. Comparisons chain: every adjacent pair must hold, like in mathematics:

3 < 5              // True
a + 1 < b * 2      // arithmetic first
"a" == "a"          // True
"a" == "b"          // False
1 < x < 10         // True when x is between 1 and 10
1 == 1 == 1         // True
OperatorMeaning
==equal (numbers compare by value across int and float; every other cross-type is always False)
!=not equal
< > <= >=ordering — numbers only (int or float, never booleans)
Ordering comparisons on strings or booleans are runtime errors. Equality across different types is False, never an error — except that numbers mix: 1 == "1" is False but 1 == 1.0 is True. A chain stops at the first false pair — later pairs are not evaluated.

Logical operators

There are no and, or, or not operators — and no !, &&, or || characters. Conditions are combined structurally instead. An and is one condition inside the other; an or is a flag set by each case; a not is an else branch or an explicit comparison with FALSE:

// and — both must hold
n = 4
if (n > 0) {
    if (n / 2 * 2 == n) {
        print("positive and even")
    }
}

// or — either may hold
s = "yes"
hit = FALSE
if (s == "y") { hit = TRUE }
if (s == "yes") { hit = TRUE }
if (hit) { print("agreed") }

// not — the condition did not hold
ok = 1 == 2
if (ok == FALSE) { print("not ok") }

A while that needs two conditions carries the second one as a break inside the body:

items = [4, 7, 9, 2]
target = 9
i = 0
found = -1
while (i < len(items)) {
    if (items[i] == target) {
        found = i
        break
    }
    i += 1
}                     // found is the position, or -1 if absent
A boolean stored in a variable or returned by a function works directly as a condition: if (is_prime(n)) { ... }. Booleans cannot be combined with arithmetic — a + b on booleans is a runtime error — so nesting and flags are the only way to join conditions.

Strings

Double quotes only. Strings are single-line — a raw newline inside a string is an error. Four escapes are supported:

"hello world"
"line one\nline two"
"tab\there"
"escaped \"quote\" and backslash \\"

Strings concatenate with +, compare with == and !=, and hold any Unicode content. They are not truthy: a string used directly as a condition is an error.

An unknown escape like "\q" and an unterminated quote are lexing errors, reported at the string's start. There is no single-quote form — 'a' is not a string.

Lists

A list holds any number of values in order — numbers, strings, booleans, even other lists. Lists are immutable: no operation changes an existing list. push(), set(), and insert() return new lists, so the result must be assigned:

nums = list()          // the empty list
nums = push(nums, 10)  // [10] — rebind, the old list is unchanged
nums = push(nums, 20)  // [10, 20]
top = nums[0]        // 10 — indexes start at 0
nums = set(nums, 0, 99) // [99, 20] — a new list with one element replaced
nums = insert(nums, 1, 15) // [99, 15, 20] — a new list with 15 placed at position 1
nums = delete_at(nums, 0) // [15, 20] — a new list without the element at position 0
both = concat(nums, [30]) // [15, 20, 30] — a new list with the two joined
m1 = [["a", [1]], ["b", [2]]]
m2 = [["b", [2]], ["a", [1]]]
print(map_equal(m1, m2))  // True — same pairs, order ignored

The subscript [ ] reads one element: l[i] is exactly get(l, i) and s[i] is exactly char(s, i) — same rules, same errors. Subscripts chain left to right, and attach to any value: a variable, a call result, a module member, a parenthesized expression:

s = "roly"
s[0]                 // 'r'
s[len(s) - 1]        // 'y' — the index is any expression
reverse_str(s)[0]     // 'y' — the subscript applies to a call result
grid[0][1]           // nested lists chain left to right

A list is written directly with brackets — any values, in any mix, including other lists:

empty = []                        // the empty list
nums = [1, 2, 3]              // [1, 2, 3]
mixed = [1, "a", TRUE, [2]]     // any values, nested too
first = nums[0]                 // 1 — the literal works everywhere a value does

Lists are also built with loops the same way strings are built with +, and list("abc") turns a string into its characters:

evens = list()
i = 0
while (i < 10) {
    if (i / 2 * 2 == i) {
        evens = push(evens, i)
    }
    i += 1
}                          // [0, 2, 4, 6, 8]

letters = list("roly")   // ['r', 'o', 'l', 'y']

Two lists compare with == structurally: same length and same elements in the same order, with elements compared under the same strict-type rule as everywhere else. Lists print and convert with str() in the Roly style: [1, 2], ["a", "b"] — string elements keep their double quotes.

Working with lists

"Changing" a list always means building a new one and rebinding the variable — that is the whole model. The toolkit:

l = push(l, x)          // append at the end
l = insert(l, i, x)       // place x at position i — the rest shift right
l = set(l, i, x)          // replace the element at position i
l = delete_at(l, i)      // drop the element at position i
l = concat(l, m)         // join two lists into one
l = sort_list(l)       // new list, sorted ascending — library, numbers only

Iterating is a while with a counter — there is no for loop in the language:

l = [10, 20, 30]
i = 0
total = 0
while (i < len(l)) {
    total += l[i]
    i += 1
}                      // total is 60

Inserting into the middle is insert(l, i, x) — position 0 inserts at the front, len(l) appends at the end:

l = insert([1, 3], 1, 99)   // [1, 99, 3]
l = insert([1, 2], 0, 0)    // [0, 1, 2] — at the front
l = insert([1, 2], 2, 3)    // [1, 2, 3] — at the end

A function can never modify your list — it returns a new one, and the caller rebinds:

fn append_nine (l) {
    return push(l, 9)
}
l = [1, 2]
l = append_nine(l)     // [1, 2, 9] — the call alone would change nothing
No aliasing is ever observable: after b = a, rebinding b with push leaves a untouched — lists behave like plain values. Nested lists build grids: grid = [[1, 2], [3, 4]], read with grid[1][0].
List literals have no trailing comma — [1, 2,] is a parse error — and there is no + between lists. The subscript is strict like char() and get(): an index outside 0..len-1 is a runtime error; there are no negative indexes. Subscripts read only — assignment through them (l[0] = x) is a parse error. A list used directly as a condition is an error, like a string.

Control Flow

if / else

The condition is any expression in parentheses; the body is a braced block. One optional else block may follow.

if (x > 10) {
    y = 1
} else {
    y = 2
}

if (x == 1) {
    y = 10
} else {
    if (x == 2) {
        y = 20
    } else {
        y = 30
    }
}
Branches are checked top to bottom — the first true condition wins, and later conditions are not evaluated at all. There is no else if: longer chains nest an if inside the else block, as above. A number condition works: zero is false, nonzero is true. A string condition is an error.
Boolean literals are TRUE and FALSE — capital letters only. Lowercase true / false are ordinary identifiers (undefined variables).

while

The condition is re-checked before every iteration. The body is a braced block.

i = 0
while (i < 10) {
    i += 1
}

Blocks

A bare braced block is itself a statement. Newlines separate statements freely; they just cannot appear inside one — see the one-line rule under Arithmetic. A semicolon works the same way as a newline separator, which keeps one-liners readable — especially with exec:

x = 1 y = 2

x = 1; y = 2
while (x > 0) { x -= 1 }; print(x)
A ; must have a statement on both sides — a trailing one is a parse error, just like a trailing comma in a list. It never appears inside an expression: f(1; 2) does not parse.

A block must contain at least one statement: { }, while (TRUE) { }, or an empty function body is a parse error. To mark a block as intentionally empty, write ... as its entire body — a placeholder for code that comes later:

fn later () { ... }

if (FALSE) { ... } else { ... }
... is legal only as the whole body of a block — { ... x = 1 } or x = ... is a parse error. Calling a function whose body is ... runs nothing; using its result is the usual did not return a value error.
x = 1 y = 2

{
    x += 1
    y += 2
}
Only calls are expression statements: f(1) or mod.tick() on its own is a statement — the call runs for its side effects and its return value is discarded. Anything else on its own is a parse error: 1 + 1, a bare variable x, l[0], f()[0] must be assigned, printed, or returned. There is also no for loop; iteration is a while with a counter, shown under Lists.

break / continue

Two jump statements, legal only inside a loop body — the parser rejects them anywhere else with 'break' outside loop. They affect the innermost enclosing loop only, and they propagate out through any nested blocks and ifs.

i = 0
while (i < 100) {
    i += 1
    if (i == 5) {
        break
    }
}
i = 0
total = 0
while (i < 10) {
    i += 1
    if (i / 2 * 2 == i) {
        continue
    }
    total += i
}
  • break terminates the innermost loop
  • continue skips the rest of the body and re-checks the condition
  • statements after a jump in the same body are not executed

Functions

A function is declared with fn, a name, parameters, and a body that returns a value. Declarations are only allowed at the top level of a program.

fn add (a, b) {
    return a + b
}

fn greet (name) {
    return "hello " + name
}

x = add(2, 3)
print(greet("roly"))

Parameters

Parameters take any value — nothing is checked at the door, exactly like Python. What the function does with a value decides whether it works: add("a", "b") is fine (string concatenation), add("a", 1) fails inside the body with operator '+' requires numeric operands. An optional type annotation — fn add (a: int, b: int) — is allowed and purely cosmetic: it is never enforced, and old annotated code keeps running. An annotation must still be one of the five type names; anything else is a parse error. No return type is declared.

Scope

Each call gets its own local scope: parameters and assignments are local and disappear when the call ends. A function sees its own locals and the globals — nothing in between. One function cannot read or change the locals of the function that called it. Global variables are readable from inside functions, but assignments are always local — a function can never modify a global. A parameter may shadow a global.

g = 10
fn f (g) { return g }  // parameter shadows the global
x = f(2)          // x is 2, g stays 10

t = 5
fn h () { t = 99 return t }
y = h()           // y is 99, t stays 5 — assignments are local
Module functions are the one exception: an assignment inside a module function updates that module's own globals — that is how modules keep state. See Modules.

Calls and recursion

A call is an expression — f(a, b) — usable anywhere a value is. Functions are pre-registered before execution, so recursion and mutual recursion work, and a function may be called before its definition appears. Recursion depth is limited to 200 calls. Arguments evaluate left to right, and the argument count is checked before any argument runs — a call with the wrong arity fails before its side effects happen.

fn fact (n) {
    if (n <= 1) { return 1 }
    return n * fact(n - 1)
}
print(fact(10))   // 3628800

return

return ends the call immediately with a value. Inside a loop, return overrides break and continue — it terminates the whole call. Multiple returns in different branches are fine. A function does not have to return — calling it as a statement line (hello("world")) simply runs its body. But a function that falls off the end produces no value, so using its result in an expression (x = hello("world")) is a runtime error. return outside a function is a parse error, just like break outside a loop.

Rules

  • argument count must match the parameter count exactly
  • values are not checked on the way in — a type mismatch surfaces inside the body, at the operation that needs the value
  • parameter names must be unique, and cannot be keywords or built-in names — fn f (len) is an error
  • redefining a function name is an error
  • functions are not values — x = f does not work, only f(...); a variable cannot take a function's name in either order — fn f () { ... } f = 5 and f = 5 fn f () { ... } are both errors
  • break / continue inside a function body but outside a loop is a parse error

print

A statement — not an expression — taking one expression in parentheses. Values print in their plain form: integers in decimal, floats in Python's spelling (1.5, 0.30000000000000004, inf), strings without quotes, booleans as True / False.

print("hello world")
print(42)
print(x + y)

i = 3
while (i > 0) {
    print(i)
    i -= 1
}

print([1, "a"])   // [1, "a"] — lists render Roly-style
print is a statement, not a function: x = print(1) is a parse error, and print cannot be used as a name.

Built-ins

built-in functions. The conversions — int(), str(), bool(), float() — are the sanctioned way to cross a type boundary. len(), char(), ord(), and format() inspect and build strings. list(), push(), insert(), delete_at(), concat(), map_equal(), get(), and set() build and read lists. input() reads a line from the user. fail() stops the program with a message.

x = int("42")        // 42 — an optional + or - sign, then digits only
y = int(TRUE)       // 1
z = int(3.9)        // 3 — floats truncate toward zero
s = str(7)          // "7"
t = str(FALSE)      // "False" — same spelling as print
u = float(7)        // 7.0
v = float("-2.5e3") // -2500.0
a = bool("")        // FALSE — the empty string, otherwise TRUE
b = bool(3)         // TRUE — zero is false, nonzero is true

n = len("hello")    // 5
c = char("hello", 1) // "e" — indexes start at 0
k = ord("e")        // 101 — the code of a single character
f = format("{} + {} = {}", 1, 2, 3)  // "1 + 2 = 3"

name = input("name? ")  // prints the prompt, reads one line — a str
age = int(input("age? "))  // the numeric read — convert explicitly

Conversion is explicit and total everywhere else: "1" == 1 is still False, but int("1") == 1 is True.
Built-in names cannot be redefined — len = 5 and fn len (...) are errors. The five conversion names are keywords in call position: x = int without parentheses is a parse error. bool() rejects lists — a list is never a condition.

format placeholders

{} takes the next argument in order; {0}, {1} pick a position and may repeat. {{ and }} produce literal braces. Mixing {} and {n} in one format string is an error, as is a placeholder without a matching argument.

format("{} and {}", 1, 2)     // "1 and 2"
format("{0}-{1}-{0}", "a", "b") // "a-b-a"
format("{{}}")                  // "{}"
format("x={}!", TRUE)           // "x=True!"
Values are converted the same way str() converts them. Extra arguments are ignored. There are no format specifications like {:05d} — compose with pad(), group(), or binary() from the library instead.

Standard Library

The standard library lives in roly/lib/ as six modules: math, fmt, strings, lists, map, and thfile. Nothing loads on its own — a library module is brought in with !import, the exclamation mark marking the library that ships with Roly. Until you import it, its names simply do not exist: gcd(48, 18) is undefined function 'gcd'.

!import math {gcd, mod}
!import fmt

print(gcd(48, 18))         // 6 — the names came in with the braces
print(fmt.group(1234567))  // 1,234,567 — qualified works with or without braces

The library holds only functions with real logic — one-liners are yours to write. A parity test is n / 2 * 2 == n, a palindrome check is s == reverse_str(s), and factorial is a five-line loop. Most library functions are ordinary Roly code — open roly/lib/ to read them; every one of them is a program you could have written yourself. Calls behave exactly like your own functions: the argument count is checked, values are not — a wrong type surfaces inside the body. The native functions (sort_list, join, reverse_list, and all of thfile) still check argument types at the door. Library calls are isolated — they never read or change your variables, only their arguments. Out-of-range arguments are errors, not special values: there is no isqrt(-1) — the function tells you what it expected.

map

A hash map over plain lists — there is no dict type in Roly, so a map is an ordinary list value you can print, pass around and compare. Any value can be a key and any value can be stored; a key's identity follows its str() rendering, so 7 and "7" are different keys.

FunctionResult
new_map()an empty map
map_set(m, k, v)a new map with k set to v — creating or replacing
map_get(m, k)the value at k — a missing key is an error; guard with map_has
map_has(m, k)TRUE when k is present
map_del(m, k)a new map without k — a missing key is an error
map_size(m)the number of entries
map_keys(m) / map_values(m)the keys / values as lists
map_items(m)[[key, value], ...] — feeds straight into map_equal
map_merge(a, b)the entries of both; on a shared key the right side wins

!import map {new_map, map_set, map_get, map_has, map_del, map_size, show}

m = new_map()
m = map_set(m, "name", "Ali")
m = map_set(m, "age", 31)
m = map_set(m, "active", TRUE)

print(show(m))            // {active: True, name: Ali, age: 31}
print(map_get(m, "age"))     // 31
print(map_has(m, "mail"))    // False
m = map_del(m, "active")
print(map_size(m))          // 2
Maps are immutable like every list — every map_set or map_del returns a new map, so rebind: m = map_set(m, "age", 32). Setting an existing key replaces its value. Internally the entries are kept sorted by the key's hash — map_keys, map_values, map_items and show render in that stored order, not key order; the order is stable for the same construction history. Feed map_items(m) into the map_equal built-in for order-independent comparison of two maps.

thfile

File operations. This is the one library module written natively — a Roly program cannot reach the outside world on its own. Everything is text, in UTF-8.

FunctionResult
read(path)the whole file as a str
write(path, content)creates or overwrites the file — TRUE
append(path, content)adds content to the end, creating the file if needed — TRUE
read_lines(path)the file as a list of lines, without the line breaks

copy(src, dst)copies a file, overwriting dst if it exists — TRUE
!import thfile {read, write, append, read_lines, exists, delete}

if (exists("log.txt")) {
    delete("log.txt")
}
write("log.txt", "start\n")
append("log.txt", "entry 1\n")
lines = read_lines("log.txt")
print(lines[0])              // start
print(len(lines))           // 2
print(thfile.size("log.txt"))  // 14 — the name works too
A relative path is relative to your program's file — run roly run proj/app.roly from anywhere and the files sit next to app.roly. Inline code (roly exec) uses the current directory instead. Absolute paths always go exactly where they say. Errors are loud, like the rest of the library: reading a missing file stops the program — check with exists first. read_lines splits on line breaks and drops one trailing empty line, so a file ending in a newline does not produce an empty last element. rename refuses to overwrite — copy does not.

Modules

A module is a Roly file placed next to your program. import runs it once and gives you its variables and functions through its name — the module's namespace keeps its members apart from your names.

import testme

x = testme.users
y = testme.setBlock(7)

Library modules

!import — with the exclamation mark — imports from the standard library that ships with Roly instead of from your directory. Everything else behaves exactly the same: qualified access, braces, running once, cycle checks.

!import math {gcd}
!import strings

print(gcd(48, 18))          // 6
print(strings.upper("hi"))  // HI
  • import math looks only next to your file; !import math looks only in the library — neither falls back to the other
  • a name may come from one source only — import math and !import math in one program is an error
  • ! is allowed only right before import, on the same line, at the top level
  • sort_list, join, and reverse_list are members of the lists module, written natively for speed — !import lists {sort_list} brings them in
  • the whole thfile module is native — its file functions are the only library functions that could not have been written in Roly

Bringing names in

With or without braces, every member stays reachable through the module's name — braces never restrict access. What braces do is bring the listed names in directly, so you can use them without writing the module name.

import testme {users, setBlock}

x = testme.users          // works
y = testme.blocks         // also works — braces do not hide anything
z = setBlock(7)           // works — the name came in with the braces
w = hidden                // error — only listed names come in
A name that comes in with braces is read live: if a module function changes users, the bare users shows the new value. Assigning to it yourself (users = 5) replaces your copy — the module keeps its own value.

Members

testme.x reads a variable; testme.f(...) calls a function — the parentheses decide, like everywhere else in Roly. Members are read-only from outside: an assignment like testme.x = 5 is a parse error. A module function can change its own globals, and later reads see the new values.

c = 0
fn bump () {
    c += 1
    return c
}
import counter
a = counter.bump()   // 1
b = counter.bump()   // 2
d = counter.c        // 2 — reads the live value

Loading

import testme looks for testme.roly in the directory of the importing file. The whole module file runs the first time it is imported — assignments compute and functions register — but its print output is discarded, so importing stays silent. Function calls you make later print normally. Errors inside a module are reported with its name.

  • a module runs once — importing it again does not re-run it
  • the same module imported by several files is one copy with one state
  • a module may refer to itself by its own name — testme.f() works inside testme.roly
  • a module's own imports are private to it
  • modules may not import each other in a cycle — circular import
  • a file cannot import the program that started the run

Rules

  • import is only allowed at the top level of a file
  • a module sees its own globals and the modules it imports — never yours
  • module functions cannot see the locals of the function calling them
  • built-in names are not module members — testme.len does not work; a module can pass on names it imported with braces — if testme does !import math {gcd}, then testme.gcd works
  • member names follow identifier rules — keywords cannot be members
  • a brace name replaces a variable with the same name, but collides with one of your functions; a brace function colliding with one of your functions or variables is an error
  • import is a keyword; it cannot be used as a variable or function name
